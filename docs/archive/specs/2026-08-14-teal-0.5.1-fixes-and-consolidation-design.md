# teal 0.5.1 — Bug fixes, component consolidation, docs IA redesign

Date: 2026-08-14
Status: Approved by user (design phase)
Release: `@kryv/teal` 0.5.0 → 0.5.1 (user explicitly accepts a hard API break in a patch release; no deprecated aliases)

## Context

`packages/teal` is a React component library (~170 components, one `.tsx` per component, flat exports in `src/index.ts`, Tailwind with `teal-u-` prefix internally, design tokens in `src/tokens.css`). `apps/docs` is a Vite + React Router docs app that renders one page per component (`pages/ModulePage.jsx`) with demos loaded on demand (`data/catalog.jsx` + `import.meta.glob`), grouped by `moduleGroups` in `apps/docs/src/data/module-meta.js`.

The user reported ~25 issues: visual bugs, interaction bugs, docs-app bugs, performance, and excessive component duplication. This spec covers all of them plus a full-library consolidation sweep.

---

## Part 1 — Library bug & visual fixes

Each fix is scoped to the listed file(s) in `packages/teal/src` unless noted.

### 1.1 ButtonGroup selected state (`ButtonGroup.tsx`, `apps/docs/src/demos/ButtonGroupDemo.jsx`)
ButtonGroup is currently layout-only (`role="group"`, seam/radius classes) with no selection concept. Add a pressed/selected treatment: when a child button is selected (aria-pressed / data-state), render it elevated with accent color so the active option visibly "pops". Update the demo to show a selectable group and cross-link SegmentedControl for single-select use cases.

### 1.2 ActionBar bottom corners (`ActionBar.tsx`, `apps/docs/src/demos/ActionBarDemo.jsx`)
`ActionBar.tsx:22-27` has no border-radius. Add bottom rounding when `position="bottom"` (match the surface radius scale, e.g. `rounded-b-2xl`). In the demo, replace hardcoded `border-gray-200`/`text-gray-600` with token colors.

### 1.3 Combobox can't toggle closed (`Combobox.tsx`)
The input's `onFocus`/`onChange` only open (lines 184–192) and `onInteractOutside` swallows anchor clicks (lines 208–211). Add click handling so clicking the input/trigger while open closes the popover (toggle semantics), without breaking typing.

### 1.4 NumberInput stepper (`NumberInput.tsx:161-180`)
Two round `size-6` buttons stacked in `flex-col` exceed the 40px field height and float with dead space. Replace with a compact joined stepper: square buttons, hairline divider between them, fits the field height (native spinbutton-like).

### 1.5 InputGroup focus ring (`InputGroup.tsx:36-37`, `styles.css:39-48`)
Align the group's `:focus-within` ring + border-color behavior with Input's `:focus-visible` treatment (same `--teal-focus-ring` token, same border transition) so the highlight matches a standalone textbox.

### 1.6 DateRangePicker range band (`DateRangePicker.tsx:353,386-395`)
Today every day cell is a 36px circle; in-range days get square `bg-primary/10` boxes with gaps between them. Make the range band connected: full-width in-range cell backgrounds, endpoints keep `bg-primary` circles with the band bleeding into them (rounded toward the outside edge).

### 1.7 PhoneInput dropdown (`PhoneInput.tsx:125-140`)
The country picker is a native `<select>` (OS-rendered menu). Rebuild it on the shared Radix popover pattern with the same `teal-popper-content teal-overlay-surface` classes and option styling as Select/Combobox.

### 1.8 SearchInput loading icon (`SearchInput.tsx:96-106`)
Spinner sits at `right-3` while the clear button sits at `right-1`, so the icon jumps position between states. Unify the slot position; add `role="status"`/accessible labeling for the loading state.

### 1.9 GlassPanel legibility (`GlassPanel.tsx:15`, `apps/docs/src/demos/GlassPanelDemo.jsx`)
No text color is set, so children inherit over a translucent blur. Set `text-on-surface` (and raise surface opacity if needed for contrast); replace the demo's hardcoded `text-gray-600` with token colors. (GlassPanel folds into Card per M21 in Part 3 — the legibility fix ships as part of that merge.)

### 1.10 Tooltip placement (`Tooltip.tsx:31,41`)
The prop is `side`; consumers/demo pass `placement`, which is silently ignored. Accept `placement` as an alias mapped to Radix `side`, and fix the docs demo.

### 1.11 BlockingOverlay legibility (`BlockingOverlay.tsx:61-67`)
Scrim is only `bg-surface/60` with no blur; busy content bleeds through under the label. Strengthen the scrim (higher opacity + `backdrop-blur`) and ensure the label/spinner meets contrast.

### 1.12 OfflineBanner legibility (`OfflineBanner.tsx:54`)
Uses a low-emphasis `bg-surface-container-high` surface for a high-priority alert. Restyle with warning-emphasis tokens (warning container bg + on-container text).

### 1.13 AnchorNav scroll-spy (`AnchorNav.tsx:11-44`, `apps/docs/src/demos/AnchorNavDemo.jsx`)
`useScrollSpy` uses `document.getElementById` with viewport root; the demo mounts two instances with duplicate section ids, and `scrollIntoView` scrolls every ancestor. Scope observation and scrolling to the nav's own container via ref; give the demo unique ids per instance.

### 1.14 SubNav demo (`apps/docs/src/demos/SubNavDemo.jsx`)
Items link to hashes with no matching page elements, so clicking looks broken. Add real anchored sections (or hash handling) to the demo so selection works. (`SubNav.tsx` itself is presentational — no library change expected.)

### 1.15 FunnelChart labels (`FunnelChart.tsx:89-98`)
Single centered `<text>` overflows narrow lower bands. Truncate to fit and fall back to an outside/legend label for bands too narrow.

### 1.16 GaugeChart visuals (`GaugeChart.tsx:104-137`)
Zones drawn at `strokeOpacity 0.3` with no track look washed out ("broken"). Add a track arc behind zones, full-opacity zone colors with rounded caps, and keep min/max labels inside the layout.

### 1.17 PieChart label halo (`PieChart.tsx:138-152`)
Labels use `stroke="var(--teal-color-surface)" strokeWidth={3} paintOrder="stroke"` — a halo inconsistent with the other charts. Remove the stroke; plain fills.

### 1.18 OrgChart connectors (`OrgChart.tsx:66-116`)
1px connector divs misalign when node widths differ; wide trees only get `overflow-x-auto`. Fix connector geometry (center on node regardless of width) and spacing.

## Part 2 — Docs app fixes (`apps/docs`)

### 2.1 Sidebar double-active (`src/components/Layout.jsx:90`)
`active = pathname.startsWith(to)` marks both `/modules/button` and `/modules/button-group` active. Replace with exact-segment matching (exact match, or `startsWith(to + '/')` for nested routes).

### 2.2 FAB/SpeedDial escaping the demo box (`src/components/Preview.jsx`)
Components use `position:fixed` and pin to the viewport. Docs-only fix (user decision — no component API change): make Preview a fixed-position containing block (e.g. `transform`/`contain` on the wrapper, or a relative wrapper + demo-level positioning) so fixed children render inside the box. Applies to FloatingActionButton, SpeedDial, and any fixed-position demos (OfflineBanner, LoadingBar, BackTop) — audit all demos using fixed components.

### 2.3 External links
Replace placeholder external hrefs (`https://status.example`, `*.example` links in `module-meta.js`, `NotificationItemDemo.jsx`, `LinkDemo.jsx`, `LauncherCardDemo.jsx`) with inert `#` links or non-navigating elements. Keep the real GitHub repo link in `Layout.jsx`.

### 2.4 Performance
`src/data/module-meta.js` is a 10,205-line module imported eagerly into the main chunk via `docs-module-registry.js` → `Layout.jsx`. Split metadata per group (lazy `import()` like demos already use in `catalog.jsx`), so the sidebar/search load a light index and full metadata loads per page. Evaluate `manualChunks` in `vite.config.js` for the library chunk. Measure before/after with the production build.

### 2.5 Information architecture
Regroup `moduleGroups` (current: Actions, Forms, Surfaces, Overlays, Feedback, Navigation, Data, Layout, Utilities) to reflect the merged component set: one nav entry per merged component, groups rebalanced so similar components sit together. Sidebar, search, and PrevNext all derive from the same catalog, so this is a data change.

## Part 3 — Component consolidation (hard break)

Old component names are deleted; no alias re-exports. Every merge includes updating: the component file(s), `src/index.ts` exports, the component's tests in `packages/teal/test/`, docs page + demos + `module-meta.js`, and any internal consumers.

Naming follows the existing flat-export convention (no `X.Item` dot-notation introduced).

### Merge groups

| # | Merged component | Absorbs | New API |
|---|------------------|---------|---------|
| M1 | **DatePicker** | MonthPicker, YearPicker, DateTimePicker, DateRangePicker | `mode: 'day'\|'month'\|'year'\|'datetime'`, `selection: 'single'\|'range'` |
| M2 | **TreeSelect** | Cascader | `display: 'tree'\|'columns'` (columns emits full path `string[]`, tree emits leaf `string`) |
| M3 | **ToggleGroup** | SegmentedControl | `variant: 'default'\|'segmented'` (segmented = sliding-pill indicator). Toggle stays standalone. |
| M4 | **Dialog** | FullscreenDialog, Drawer, BottomSheet | `placement: 'center'\|'fullscreen'\|'left'\|'right'\|'bottom'` (+ BottomSheet's `snap`) |
| M5 | **Alert** | Banner, Callout | `appearance: 'surface'\|'banner'\|'callout'`, `accent?: boolean`, `action` slot |
| M6 | **Slider** | RangeSlider | `range?: boolean` / `value: number \| [number, number]` |
| M7 | **Table** | DataTable | absorbs sorting + row-selection props (DataTableColumn is already a superset) |
| M8 | **Menu** | ContextMenu | `mode: 'dropdown'\|'context'`; Menubar keeps its root but shares the item renderer internally |
| M9 | **EmptyState** | Result | optional `status` (icon/tint map) |
| M10 | **AnchorNav** | TableOfContents | nested `items` support (builds on fix 1.13) |
| M11 | **LineChart** | AreaChart | `type: 'line'\|'area'` (+ `stacked`) |
| M12 | **Sidebar** | VerticalNav, SideRail | `collapsed`/`mode: 'rail'\|'full'` absorbed |
| M13 | **StatusDot** | PulseDot | `pulse?: boolean` |
| M14 | **RadioGroup** | RadioCard | `variant: 'radio'\|'card'` |
| M15 | **Checkbox** | CheckboxCard | `variant: 'checkbox'\|'card'` |
| M16 | **Combobox** | MultiSelect | `multiple?: boolean` |
| M17 | **TextArea** | AutosizeTextarea | `autosize?: boolean`, `minRows`/`maxRows` |
| M18 | **Popover** | HoverCard | `openOn: 'click'\|'hover'` |
| M19 | **FloatingActionButton** | SpeedDial | optional `actions[]` (fan-out) |
| M20 | **Progress** | ProgressCircle | `shape: 'bar'\|'circle'` |
| M21 | **Card** | Panel, GlassPanel | `title`/`actions` header props, `variant: 'default'\|'glass'` (glass gets legibility fix 1.9) |
| M22 | **Command** | SearchOverlay | render-prop/children API absorbed into Command |
| M23 | **NavigationMenu** | MegaMenu | single top-nav menu on the Radix navigation-menu root |
| M24 | **Input** | SearchInput, PasswordInput | `clearable?: boolean`, `loading?: boolean` (with fix 1.8), built-in password reveal for `type="password"`. NumberInput stays separate (fix 1.4 applies). |

### Explicitly NOT merged
Switch/Checkbox (different ARIA roles), AlertDialog/PromptDialog (alert-dialog semantics), Tooltip (non-interactive inverse surface), TreeGrid (treegrid pattern), Meter (meter role), Tabs (tablist semantics), PinInput/TagsInput/MaskedInput/CurrencyInput/MentionInput/PhoneInput (distinct value formats), radial & special charts (Pie/Gauge/Radar/Funnel/Scatter/Gantt/Org/Sparkline/Heatmap — different geometry/data), Toast vs NotificationCenter, layout primitives, behavior-preset buttons (CopyButton/ShareButton/BackTop/ThemeToggle), ImageViewer vs Lightbox, Timeline/ActivityFeed/CommentThread.

### Internal dedup (no API change)
- Shared date utils + month grid extracted from Calendar/DatePicker/DateTimePicker/MonthPicker/YearPicker into one internal module (consumed by M1).
- Single shared `useScrollSpy` (AnchorNav/TableOfContents → M10).
- Single shared MenuItem renderer (Menu/ContextMenu/Menubar → M8).
- Shared form-field scaffolding (label/description/error block repeated across ~15 inputs) extracted into an internal helper.

## Part 4 — Tests & release

- **Unit tests:** one spec per merged component covering every absorbed mode (e.g. DatePicker spec covers day/month/year/datetime/range). Delete specs of removed components; update cross-cutting suites (`a11y.test.tsx`, `ssr.test.tsx`, `forms.test.tsx`, `tokens.test.ts`).
- **Docs tests:** Playwright suite (`apps/docs/tests/docs.spec.js`) — full-module axe sweep and visual baselines must pass; update baselines for changed visuals (range picker, gauge, pie, funnel, action bar, etc.).
- **Verification gate:** `npm run verify` (lint + typecheck + unit tests + generated-token check + registry validation + build + pack verify) green.
- **Release:** changeset for 0.5.1. CHANGELOG gets a migration table (old component → new usage) since this is a hard break. Note in the changelog that 0.5.1 intentionally ships breaking changes (user decision, semver exception).

## Error handling / risks

- Merged components must preserve each absorbed component's a11y behavior (roles, roving tabindex, focus restore) — covered by per-mode tests and the axe sweep.
- Hard break risk is accepted; mitigated by the changelog migration table.
- Docs regroup changes URLs only if module ids change — keep existing module ids (slug) for merged entries where possible so external bookmarks survive.

## Out of scope

- New components or features beyond what the merges produce.
- Speculative merges (Heatmap+CalendarHeatmap, NavRail/Dock/BottomNav, Badge+Chip, OfflineBanner+NetworkStatus, ActionBar/BulkActionBar/Toolbar family, timer text displays).
- Library build restructure (`preserveModules` per-component entries) — noted as future work; 0.5.1 does docs-side perf only.
